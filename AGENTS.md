# Repository Guidelines

## Project Structure & Module Organization

This repository is a project portfolio. The active app is the BinoCart static web and Android/Capacitor prototype in `Personal Projects/Barcode Scanner/`.

- `index.html` is the Market Intel/Pulse page.
- `scan.html`, `list.html`, `history.html`, `saved.html`, `receipts.html`, and `profile.html` are separate app views.
- `app.js` contains scan, lookup, Pulse, cart, profile, product-detail, and receipt prototype logic for the Intel/Scan experience.
- `pages.js` contains shared page behaviors for non-scan pages, including receipt review, profile receipt memory, and price memory graph interactions.
- `styles.css` contains the app-wide responsive styling.
- `tests/` contains Node `node:test` coverage for app logic, profile flows, static page contracts, and asset contracts.
- `scripts/` contains local review, receipt API, SQLite receipt DB worker, web build, Capacitor, and Android helper scripts.
- `www/` is generated by `npm run build:web` for Capacitor; avoid hand-editing it.
- `assets/brand/` contains BinoCart logos, icons, mascot images, brand-system references, raw screenshots, and a `manifest.csv` asset index.

The app can be served directly as static files, tested with npm, deployed by GitHub Pages, and packaged for Android through Capacitor.

## Build, Test, and Development Commands

Run the app locally from the BinoCart folder:

```powershell
cd "Personal Projects/Barcode Scanner"
python -m http.server 4173
```

Open `http://127.0.0.1:4173/`. For local network testing, use `python -m http.server 4173 --bind 0.0.0.0` and open the PC LAN address from the other device. Use GitHub Pages for mobile camera testing because browser camera permissions generally require HTTPS.

Run a local review server:

```powershell
npm run review
```

Run the receipt parser API when testing OpenAI-backed receipt parsing:

```powershell
npm run api:receipts
```

Run automated checks from the same folder:

```powershell
npm test
```

Build the Capacitor web bundle:

```powershell
npm run build:web
```

Do not run `npm test` and `npm run build:web` at the same time; the build rewrites `www/` while tests may inspect generated static assets.

Useful repository checks:

```powershell
git status --short
rg "BinoCart"
```

## Coding Style & Naming Conventions

Use plain HTML, CSS, and JavaScript. Keep indentation consistent with nearby files, typically two spaces in HTML/CSS/JS blocks. Prefer descriptive camelCase names for JavaScript variables and functions, and kebab-case for CSS classes and asset filenames, such as `bino-thinking.png` or `logo-primary-horizontal.png`.

Keep UI copy concise and customer-facing. BinoCart recommendations should feel transparent, objective, and confidence-building. Pulse and Explore surfaces should feel like independent shopping intelligence, not retailer promotion.

## Testing Guidelines

Automated tests use Node's built-in `node:test` runner under `tests/`. Add tests for static page wiring, brand asset contracts, Pulse/cart logic, receipt database behavior, and localStorage workflows when changing shared behavior. For scanner-related changes, still manually verify the camera path where supported. For profile, list, saved, archive, receipt, and developer UI setting changes, test browser localStorage persistence by refreshing the page.

## Commit & Pull Request Guidelines

Recent commits use short imperative summaries, for example `Add receipt memory prototype` and `Organize BinoCart brand assets`. Follow that style: concise, present-tense, and scoped to the change.

Pull requests should include a short description, affected pages, manual test notes, and screenshots for visual/UI changes. If brand assets change, mention whether files are raw references, generated PNG placeholders, or production-ready exports.

## Agent-Specific Instructions

Do not commit `.codex-remote-attachments/`. Preserve raw brand screenshots under `assets/brand/reference/raw/`; place usable app assets in the appropriate `assets/brand/` subfolder and update `manifest.csv` when adding generated assets.

When pushing changes, include the GitHub Pages app URL in the final response:
`https://ajth-work.github.io/projects/Personal%20Projects/Barcode%20Scanner/`.

Do not commit `.env` or `data/`; receipt API credentials and local SQLite databases must stay local. Use `.env.example` for documented variables only.
